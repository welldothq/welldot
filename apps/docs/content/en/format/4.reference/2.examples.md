The format ships with 19 complete example files. Each one is valid and each shows a different situation: rock types, construction styles, test records, permits, water quality and the messy records real archives contain. Use them to learn the format, to test software and as starting points for your own files.

They are built on real wells from SIAGAS, the groundwater registry of the Geological Survey of Brazil: region, geology, construction and the order of magnitude of test values come from the registry. Names, identifiers, permits, analyses and readings are invented but consistent. Every file says so in an `x-welldot-example` block.

## Get the files

- Download: `https://welldot.org/examples/<file>.well` (the links below).
- From npm: `@welldot/core/examples/<file>.well`, installed with [`@welldot/core`](/core/getting-started/installation).
- On GitHub: [`packages/core/examples`](https://github.com/welldothq/welldot/tree/main/packages/core/examples), with a README on how they were made.
- In the editor: [welldot.org](https://welldot.org) offers them when you start a new well.

## Use them in these docs

Writers can draw any example on a page with its id:

```mdc
::well-preview{example="santarem-pa-jorrante-alter-do-chao"}
::
```

See [Content components](/contributing/components).

## How they are checked

The `@welldot/core` test suite checks that every example parses, survives a serialize and parse round trip, and matches the gallery index. This site's CI validates every example a page uses.
